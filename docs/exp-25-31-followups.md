## #25 なぜ長文脈で L0 より高精度になるのか(トークン量 vs 意味密度)
N=600 メモリで、L0 / sudachi-m / **L0 を m のトークン数に縮めた L0-tm** / **m を L0 のトークン数に伸ばした m-tm** を比較(正解メモリは全条件に必ず含まれる)。質問を 2 サンプル(状態QA計 120 問)合算:

| 条件 | 正答率(95%CI) | L0 との差(L1のみ正解:L0のみ正解, p) |
|---|---|---|
| L0@600 | 67.5%(0.59-0.75) | |
| sudachi-m@600 | 75.0%(0.67-0.82) | 26:17, p=0.22 |
| L0-tm@534 | 70.8% | 12:8, p=0.50 |
| m-tm@674 | 70.8% | 22:18, p=0.64 |

N=300(120 問合算)は L0 77.5%、m 78.3%、L0-tm 76.7%、m-tm 78.3% で差なし(p=1.0)。N=100 も差なし。
- **#20 の「N=600 で m が +20pt(p=0.022)」は再現しなかった**。同じ質問サンプルでも別サンプルを足すと差は +7.5pt(p=0.22)に縮み、有意ではない。#20 の p 値の一部は偶然だった可能性が高い。
- 同じトークン数では L0-tm と m-tm がほぼ同じ(70.8%)で、**意味密度仮説(H2)を支持する証拠はない。トークン削減(H1)と文脈長(lost-in-the-middle の軽減)で大部分が説明できる中立的な結果**に近い。ただし 120 問でも検出力は低く、「大きな効果はない」までしか言えない。
- 位置別(N=600, 第1サンプル): L0 は中央が高く両端が低い(0.50/0.58/1.00/0.58/0.42)のに対し、m は 0.75/0.67/0.92/0.75/0.75 と平坦寄りだが、有意な差ではない。
- qwen3-8b の再現は LM Studio が 4,000 トークン超で停止・文字化けしたため N=100 のみ(L0 57% / m 57% / L0-tm 57% / m-tm 53%、差なし)。Qwen3 のトークナイザでは m は L0 より 25% 長い。
- 時期QA は L1 が不利(例: N=600 で L0 95% / m 80%)。時間表現が落ちやすい。
- #29 に続く内部表現解析は下記。

## #30 圧縮限界・最小十分表現(gemma, N=300, L0 80%)
1 要素ずつ消す/残す ablation(28 条件、Pareto は `chart_pareto_google_gemma-4-12b.svg`):
- **削除しても壊れない(表層文法)**: フィラー(80%)、丁寧語(83%)、助詞(80%)、重複主語(ginza-d 80%)、文区切り(83%)、たい/う/らしい・みたい(83〜85%)。フィラー・丁寧語・助詞をまとめて消した surface-stripped は 85%(トークン 0.84)、さらに状態の標識を正規化した版は 88%(0.84)で、L0 を下回らない。活用形を残す m+conjugation も 87%。
- **壊れる(意味・関係)**: 状態標識を全部消す content-only 55%(p=0.004)、かも(不確実性)68%、ない(否定)73%、語順の逆転 27%、シャッフル 47%、主語(人名)の除去 37%。naive(ひらがな連の削除)は 35%。個別の標識の差は 60 問では有意でなく(p>0.1)、傾向として読む。
- 最初に壊れる意味カテゴリ: 否定と不確実性、その次に語順(係り受けの代替)と主語。
- **最小十分表現(経験的)**: 「内容語 + 状態標識(ない/た/かも)+ 語順 + 主語」を保ち、表層文法(助詞・丁寧語・フィラー)を落とした表現。トークン削減は gemma で 16%(0.84)、sudachi-g 相当の連結で 30%(0.70)まで精度を保てたが、後者は N=600 で崩れる(#20)。

## #26 Tokenizer-aware L1
同じ意味を、単語区切り(空白/なし/・/,)×文区切り×標識の書き方(かな/1漢字/ASCII)×活用語の表記(見出し語/かな)=96 通りで書き分け、tokenizer ごとにトークン最小のスタイルを選択(状態復元 97% 以上・完了への誤読 0 を制約。較正 400 件、held-out 600 件)。`tokaware.json`、`chart_tokaware_ratio.svg`:
- 汎用 m の L1/L0 は cl100k 0.84、o200k 0.84、**Qwen3 1.21**、gemma2 0.88、llama3.1 0.90、mistral-nemo 0.91、DeepSeek 0.98。トークナイザ別の最小スタイルは 0.59〜0.66 で、**語を区切らない連結形が全 tokenizer で最小**。
- 「単語区切りと文区切りを残す」読みやすさ制約をつけると 0.74〜0.89 で、Qwen3 では 1.03(削減なし)。トークナイザ別に探索するだけの利点は主に Qwen3 で大きい(m 1.21 → 最小 0.66 / 制約付き 1.03)。
- gemma QA(N=300): gemma 用の最小スタイル(0.67)は 83% で L0(80%)と同等、TTFT 57 → 41 秒(-28%)。汎用 g(0.70)は 75%、読みやすさ制約付き(0.86)は 70%。差は有意でない(p>0.28)。別の tokenizer(Qwen3)用に選んだスタイルでも 80%・0.67 で、**この条件では tokenizer 固有の最適化が精度や速度に与える差は検出できなかった**。
- qwen3-8b(N=100): 汎用 m はトークン +26%・TTFT 悪化(13.2 → 15.8 秒)、qwen 用最小スタイルは 0.72 で TTFT 9.4 秒(-29%)、精度は全条件 53〜65% で差なし。
- 設計指針: `compile_l1(text, target_tokenizer)`(`tokaware.py`)で、スタイル格子を較正セット上で全探索し、状態復元の制約を満たす最小を選ぶ。ただし精度制約は LLM でなくルールなので、**最終選択は LLM での QA 検証を必須**にする(連結形は長文脈で劣化する)。

## #27 自然会話での再現(LLM 生成の会話)
実会話コーパスは取得していないため、**gemma-4-12b が仕様(人物・出来事・状態・現象)から書いた LINE 風の会話**(主語省略・指示語・言い直し・断片・俗語・複数発言に分かれた事実、誤字は規則で注入)90 件を使用。生成した会話を gemma が原文から正しい状態に読み戻せた 76 件を残した(**L0 に有利な選別**。生成時の曖昧さも残る)。76 件を 1 つの記憶ストアにして QA:

| 表現 | トークン比 | 正答率 | L0 との差(p) |
|---|---|---|---|
| L0 | 1.00 | 82.9% | |
| sudachi-m | 0.69 | 71.1% | 2:11, p=0.022 |
| sudachi-g | 0.58 | 77.6% | 3:7, p=0.34 |
| naive | 0.43 | 44.7% | 4:33, p<0.001 |
| refined-r1 | 0.78 | 80.3% | 2:4, p=0.69 |
| refined-r2 | 0.82 | 82.9% | 2:2, p=1.0 |

- 合成データと違い、**自然会話では汎用 m は有意に L0 を下回った**。失敗は否定(NOT_DONE 0.86 → 0.43)、言い直し(0.82 → 0.68)、俗語(0.94 → 0.71)、指示語(0.81 → 0.69)で、伝聞の「〜んだって」の「って」や口語の感動詞・接続詞が落ちていた。
- この分析から精製ルールを作った(refined-r1: 活用形・感動詞・接続詞・フィラー・伝聞の「って」を残す、r2: さらに格助詞と接続を残す)。r2 は L0 と同じ 82.9% でトークン -18%(TTFT 79 → 65 秒)。**精製は評価した同じ会話の失敗から作ったため過学習の可能性があり、別の会話セットでの検証は未実施**。
- 合成データの規則性が #20 の結果を過大評価していた可能性が高い。qwen3-8b は 4,000 トークン超の文脈で LM Studio が文字化けを返したため評価できなかった。

## #28 L0/L1 Dual-Index RAG(メモリ 10,000 件・300 クエリ)
BM25 は L1 側(語彙)、ベクトルは L0 側(意味)で融合(RRF k=60、重み付きの重みは開発クエリで選択)。Recall@5(MRR):

| 方式 | nomic | qwen3-embedding |
|---|---|---|
| BM25(L0) | 0.76(0.61) | 同左 |
| BM25(L1) | 0.93(0.87) | 同左 |
| Vector(L0) | 0.55(0.42) | 0.93(0.85) |
| Vector(L1) | 0.58(0.42) | 0.77(0.76) |
| Hybrid(L0 のみ) | 0.85(0.60) | 0.94(0.80) |
| **Dual = BM25(L1)+Vector(L0)** | 0.82(0.62) | **0.97(0.90)** |
| Dual + 2-view クエリ | 0.82(0.64) | 0.99(0.92) |
| 重み付き Dual | 0.93(0.87)(重み 0.9) | 0.98(0.93)(重み 0.6) |

- **qwen3-embedding(semantic が強い)では Dual が最良**(2-view で R@5 0.99)。nomic(semantic が弱い)では BM25(L1)単独が最良で、融合はむしろ下げる。**相補性は semantic 側が十分強いときだけ成立する**。
- BM25(L1)は L0 の 1/4 のクエリ時間(14.6 vs 56 ms)、転置索引 45% 減(ポスティング 8.7 万 vs 15.7 万)、テキスト 38% 減(59 万 vs 94 万 B)。qwen3-embedding のクエリ埋め込みは 29 ms 追加。
- 再ランカー: 使える cross-encoder がなく「BM25(L1)上位 50 件を Vector(L0) で並べ替え」で代用(qwen3 で 0.93、Dual に及ばず)。LLM 再ランカーは未実施。
- 最終QA(gemma, 上位 5 件, 60 問): Dual で L0 を渡すと 95%(取得ヒット率 98%)、BM25(L0) は 73%(同 73%)。Hybrid(L0 のみ)・quad も 95% で、**最終精度では Dual の優位は示せない**。LLM に L1 を渡すと精度が下がる(Dual 88%、Vector 80%)ので、**検索は L1、LLM への入力は元の L0** が妥当。

## #31 多言語パーサベース L1(Semantic Density Convergence)
同じ事実 600 件(人物×12 出来事×7 状態×時期)を日・英・韓・中でテンプレート描画し、言語ごとの既存解析器(ja SudachiPy、ko Kiwi、zh jieba、en spaCy の lookup 見出し語化+機能語表。**統計タガーが取得できなかったため英語は規則ベース**)で決定的に L1 化(LLM なし)。
- **トークン**: tok/fact の言語間 CV(平均の標準偏差/平均)は 7 トークナイザすべてで L1 < L0(例: o200k 0.189 → 0.118、gemma2 0.312 → 0.116、事実のブートストラップで P(CV L1<L0)=1.00)。マーカーを全言語で同じ ASCII にしても、標識を全部消した content-only でも 6/7 で成立(mistral-nemo のみ悪化)。事実ごとの言語間 CV も 7/7 で低下。**ただし言語は 4 つで、CI は事実のリサンプリングのみ(言語の標本不足は扱えない)。素材は構造が揃ったテンプレートで、実際の文での収束は未検証**。
- **QA(gemma, N=300, 60 問)**: 収束してもQA は保てない。L0 → L1 → L1n(標識を各言語の語で表記): 日 70% → 68%、英 90% → 73% → 85%、韓 70% → 57% → 45%、中 90% → 40% → 72%。中国語 L1 は文字数が逆に増え(10.4 → 13.9 字)、ASCII ラベルの可能性・未決定が壊れた(0/11、0/8)。ネイティブ語のマーカーにすると中国語・英語は大きく回復するが、韓国語は悪化した(伝聞 1/13)。
- 結論: 「言語ごとの決定的 L1 で tok/fact は収束する」は支持されるが、**収束した表現が意味を保つ(最小十分表現になる)ことは言語・マーカー設計に依存**し、日本語以外では未達。#21(7 言語)は本件の拡張として残る。

## #29 Transformer は L0 と L1 をどう読んでいるか
動かせる唯一のオープンウェイトの小型モデル Qwen3-1.7B(MLX 4bit)で、最終トークンの層ごと・ヘッドごとの注意、隠れ状態、正解logit余裕を記録(N=100/250、正解位置 5 通り、条件は L0/m/g と、L0 を m・g のトークン数に調整した L0-tm)。`attn*.json`(隠れ状態の配列 `*_hidden.npz` は 137 MB のため未コミット。`python -m machine_kanbun.jpattn 100 8 attn` で再生成):
- このモデルは課題を解けない(正答率 0.23〜0.45。4 択のランダムは 0.25)ため、**L0 と L1 の差を内部表現から検出できなかった**。最終トークンの注意は質問・指示部(約 39%)と先頭(約 55%、attention sink)に集中し、正解メモリは条件によらず 0.1〜0.3% だった。人名・出来事・状態トークンへの注意量にも L0/L1 差はなかった(1 つのヘッドの最大でも正解メモリへ約 1%、0.009〜0.014)。なお m の人名スパンは姓名の間に空白が入って文字列一致で取れず欠損(nan)で、注釈の限界。
- N=250 の位置別: **メモリの中央(位置 0.5)で正答率が全条件で 0.00**(先頭・末尾は 0.25〜0.75)で、lost-in-the-middle が出ている。L1(m・g)でも同じで、軽減は確認できない。
- 隠れ状態の最終層 cosine(L0 との類似)は 0.96〜0.99。L1 は L0-tm より少し離れる(0.96 vs 0.99)が、小さな変化。正解メモリへの注意量と正解logit余裕の相関はプロンプト単位で -0.1〜+0.5(n=20〜80 で不安定)。
- 結論: 仮説(L1 で重要トークンへの注意が集中する)は、このモデルでは検証不能。より大きい(かつ注意を取り出せる)モデルが必要。

## 限界
- 評価 60 問/条件(合算で 120)では、数ポイントの差は有意にならない。多重比較の補正はしていない。
- #20 の結果の一部(N=600 の優位)は再現せず、データの規則性・質問サンプルへの依存が大きい。
- 自然会話は LLM 生成で、gemma 自身が読める会話に絞っているため L0 に有利。精製L1 は同じデータからの学習で過学習の可能性。
- qwen3-8b は LM Studio が長い文脈で不安定なため N=100 のみ。MLX 解析は小型モデルのみ。
- 英語パーサは規則ベース、言語は 4 つ。7 言語(#21)は未実施。
