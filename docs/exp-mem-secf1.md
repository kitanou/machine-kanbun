# Issue #59(Meta #56 Priority 2): SeCF-L1 を Long-term Memory 表現にしたときの検索と回答

[← README に戻る](../README.md) ・ [用語(NF/SCF/SeCF)](terminology.md) ・ [#28 Dual-Index](exp-25-31-followups.md)

SeCF-L1(簡潔な自然言語への書き直し)を記憶の保存表現にしたとき、NF・SCF-L1 と比べて検索(類似エピソードの混同を含む)と、検索結果を使った回答がどう変わるかを測る。`machine_kanbun/jpmem.py`(`prep` / `retr` / `qa` / `report`)、`scripts/run_mem59.sh`、結果は [results/jp4/mem_report.md](../results/jp4/mem_report.md)・`retrieval.json`・`qa_google_gemma-4-12b.jsonl`。

**設計**: #28 と同じ記憶ベンチ(`jpdata`、同じ出来事・別の人物と、同じ人物・別の出来事の類似エピソードを含む)N=1,000 件、クエリ 150 件。保存表現は NF / SCF-L1(sudachi-m)/ SeCF-L1(gemma の書き直し。クエリも同じ表現に変換)。検索は BM25 と qwen3-embedding(各表現)、RRF の融合(Dual = BM25(表現 X)+ベクトル(NF)、Hybrid = BM25 と ベクトルを同じ表現 X で)。回答は検索 top-5 を各表現で gemma(温度 0)に渡し、#20 と同じ 3 択(はい / いいえ / 未確定)を 60 問で採点。

## 結果

**検索(R@1、150 クエリ)**
| 戦略 | NF | SCF-L1 | SeCF-L1 |
|---|---|---|---|
| BM25 | 0.727 | **0.893** | 0.807 |
| ベクトル(qwen3-embedding) | **0.947** | 0.813 | 0.900 |
| Hybrid(同じ表現の BM25 + ベクトル) | 0.933 | 0.900 | 0.933 |
| Dual(BM25 = 表現 X、ベクトル = NF) | — | **0.980** | 0.927 |

- **H1(SeCF-L1 はベクトル検索で NF 以上、混同も少ない)は支持されない**: ベクトル検索の R@1 は SeCF-L1 0.900 で NF 0.947 より -4.7pt(p=0.068)、top-1 の誤りのうち「同出来事・別人物」も NF 0.053 に対し 0.087。SCF-L1 のベクトル(0.813)よりは +8.7pt(p=0.006)高い。
- **H2(SeCF-L1 の BM25 は SCF-L1 に及ばない)は支持**: SeCF-L1 の BM25 は SCF-L1 より -8.7pt(p=0.010)、NF の BM25 より +8.0pt(p=0.017)。SeCF-L1 は語彙が NF から離れるが、SCF-L1 ほど正規化されない。
- **最良の検索は #28 と同じ Dual(BM25 = SCF-L1、ベクトル = NF)**: R@1 0.980。SeCF-L1 を語彙側に使った Dual は 0.927(-5.3pt、p=0.008)で、Hybrid(同じ表現)では SeCF-L1 は NF と同じ(0.933、差 0)。**SeCF-L1 に検索上の独自の利点は見えない**。
- **誤りの種類**: top-1 の誤りの大半は「同出来事・別人物」(例: BM25 NF 0.26、SCF-L1 0.107、SeCF-L1 0.18。ベクトル NF 0.053、SeCF-L1 0.087)。人物名の一致が語彙検索で効き、SCF-L1 の BM25 が混同を最も減らす。

**回答(60 問、検索結果の top-5 を各表現で渡す)**
| 検索 | 渡す表現 | 正答率 | プロンプト tok |
|---|---|---|---|
| Hybrid(各表現) | NF | 0.850 | 240 |
| Hybrid(各表現) | SCF-L1 | 0.867 | 225 |
| Hybrid(各表現) | SeCF-L1 | **0.967**(vs NF +11.7pt p=0.040) | 224 |
| Dual(検索を固定) | NF | 0.917 | 238 |
| Dual(検索を固定) | SCF-L1 | 0.833(vs NF -8.3pt p=0.18) | 225 |
| Dual(検索を固定) | SeCF-L1 | 0.933(vs NF +1.7pt p=1.00) | 220 |

- **H3(SeCF-L1 を渡すと NF 並みの精度)は精度の点で支持、トークン削減(≥10%)は満たさない**: 検索を固定(Dual、ヒット率はどれも 1.00)すると SeCF-L1 は NF と同じ(+1.7pt)、SCF-L1 は -8.3pt(有意でない)。トークンは NF 238〜240 に対し SeCF-L1 220〜224(-7〜8%)で ≥10% に届かない。
- **end-to-end(表現ごとの Hybrid)では SeCF-L1 が NF を +11.7pt 上回る**(p=0.040、補正なし)。ただし**同じ事実でも検索順序が変わるだけで NF の正答率が 0.850(Hybrid)から 0.917(Dual)へ動く**(ヒット率はどちらも 1.00)ので、順序の影響(±7pt 程度)を含む。この +11.7pt は SeCF-L1 の表現効果と断定できない。誤答の種類: 「未確定 → いいえ」が NF 6 件、SCF-L1 7 件に対し SeCF-L1 は 2 件(迷い・伝聞・可能性の区別が SeCF-L1 で残る傾向)。
- **H4(コスト)は支持**: SeCF-L1 の変換は 1 件平均 1,234 ms(LLM)、SCF-L1 は 1 ms 未満。保存は 1,000 件で NF 97,079 バイト、SCF-L1 60,797、SeCF-L1 69,350(NF 比 -29%)。回答 1 回あたりの節約は top-5 で約 16 トークン(1 記憶あたり約 3 トークン、約 0.03 秒の prefill)で、変換の 1.2 秒を回収するには**1 件の記憶が約 40 回検索される**必要がある(N が小さい/検索頻度が低い運用では回収できない)。

## #56 の仮説への示唆
- **H2(SeCF-L1 は検索・再利用しやすい Memory 表現になり得る)**: 検索の面では支持されない(ベクトルは NF 以下、BM25 は SCF-L1 以下、最良の融合は SCF-L1 + NF)。**LLM に渡す記憶の表現としては NF 以上(精度)で、SCF-L1 より正確**(Dual 固定で +10pt、p=0.109)だが、トークン削減は 7〜8% と小さい。
- 実運用の組み合わせの候補: 検索は Dual(BM25 = SCF-L1、ベクトル = NF)、LLM への入力は SeCF-L1 または NF(SeCF-L1 は変換コストを払って得る節約が小さい)。**N=1,000・1 回あたり 1.2 秒の変換を払う価値は、この規模では示せない**。

## 限界
合成のテンプレート記憶(同じ構文の繰り返し、クエリも定型)N=1,000、150 クエリ、QA は 60 問で順序効果を含む。RRF は重みなし(#28 の重み付き Dual は未使用)。R@1 は rank(同点では top-1 の内訳より高く出る。Dual SCF-L1 は R@1 0.980 に対し top-1 正解 0.953)。SeCF-L1 の書き直しは gemma(回答も gemma)。変換 2,010 件(#33・#57 の分を含むキャッシュ全体)のうち原文へのフォールバックは 1 件。**NF への再構成可能性、N=10,000 への拡大、数日後の再利用(長期の状態変化・重複の統合)は未実施**(#56 Priority 2 の一部のみ)。
