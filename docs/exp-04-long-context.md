# Issue #4: 長文コンテキスト評価 (2k〜32k)

[← README に戻る](../README.md) ・ [用語(NF/SCF/SeCF)](terminology.md)

> 表記: 本書の L0 = NF、L1 = SeCF-L1(構造化 Fact から作る電報体)、L5 / MKW / IR = SeCF-L5(Issue #35)。以下は当時の旧称のまま記述している。

`Model × Representation × Legend × Context length` の4軸で評価。完全版は [results/long_report.md](../results/long_report.md)、
生データは `results/long/*.jsonl`、演算子別プロファイルは `results/model_profiles.json`。

```bash
scripts/run_long.sh [model...]        # 再開可能。LM Studio が固まったら自動で再ロードして再開
python3 -m machine_kanbun longqa --model google/gemma-4-12b --lengths 2000 8000 --variants L1 L5:none L5:minimal
python3 -m machine_kanbun longreport
```

- 生成器 `gen.py`: 人物/案件/催事を乱数生成し、同一 facts から全形式を出力。文脈長は L0 の o200k トークン数で定義(圧縮形式はその結果として短くなる)。
  問題は意味カテゴリ別に層化し、**横断推論**(案件→担当者→職業、催事間の定員比較)と**参照解決**(愛称)を含む。48 問/文書。seed 固定で決定的。
- 形式: JSON / L0〜L5 / **Adaptive**(`data/policies.json` のモデル別方針で fact の種類ごとに圧縮度を変える)。
- 凡例: none / full(約62 tok) / minimal(`疑`のみ, 約14 tok) / category(質問カテゴリの演算子のみ, 約10 tok)。
- 計測: 文脈トークン(モデル実測 − 空文脈基準)、各変種1問目を**コールド**(prefix cache 無効化)として TTFT/prefill、2問目以降を**ウォーム**として別計上、
  実効凡例コスト(凡例tok / 再利用回数 R)と損益分岐、メモリ差分(best-effort)、L1 との対応あり符号検定、Pareto frontier。

| 変種 | 2k | 8k | 16k | 32k | 文脈tok(8k) | vs L0 |

| Adaptive + minimal | 100% | 100% | 96% | 92% | 3135 | -54% |

## 所見(誤差を踏まえた結論)
1. **MKW は L1(日本語要約)と統計的に区別できない。** gemma で L1 との差は全変種で p ≥ 0.07(符号検定。JSON のみ L1 より悪い方向)。
   トークン量は L5 が L1 より約 2〜3% 多く、精度も同等。**このデータでは「漢文化」独自の利点は示せていない。** 一方で L0 比 -54% のトークン削減と、L0 と同等の精度は確認できた。
2. **TTFT は文脈トークンに比例する。** prefill は約 100 tok/s で長さによらずほぼ一定(gemma)。L0 比 TTFT は約 -55%(16k: 144 秒 → 63 秒)。ただしこれは L1 でも同じで、MKW 固有の効果ではない。ウォーム(キャッシュ命中)の TTFT は約 2〜4 秒で形式差なし。
3. **凡例は精度を有意に改善しなかった。** 16k で L5 の full が +4.2pt、minimal が +2.1pt だが 1〜2 問差。L1 より短くならないため、L1 比の損益分岐は常に「回収不能」。L0 比では 1〜8 facts で回収できるが、それは L1 でも得られる削減。
4. **Adaptive は固定 L5 に対して利得なし**(同一トークン量、精度も同等)。方針は issue 例の手設定で、モデルの Operator Profile から学習したものではない。
5. **32k で L5 系が L1 より約 4pt 低い**(92% vs 96%)が、差は 2 問(p は有意でない)。L5 系 3 変種は同じ問題を落としており、独立な証拠ではない。落とした問題は否定(無)2・因果1・横断推論1。
   「駐車場有」を「ない」と読むなど、`無`/`有` の取り違えが見られた。
6. **JSON はトークンが +44%、精度も最低**(92〜94%)。16k では gemma の実効コンテキスト(19456)に収まらなかった。
7. **演算子別**: 不・未・非・禁・疑・若・過今将 は L2〜L5 でほぼ 100%。弱いのは 無(83%, L5)、故(82%, L5)、`>`(86%)。qwen(2k のみ)の `疑` は各変種 n=3 で 0/3〜3/3 とばらつく(L1・JSON・adaptive は 0/3、L0・L5 凡例なしは 3/3)。n が小さく、`疑` 固有の弱点とも MKW 固有の弱点とも結論できない。

## 制約・未達(正直な記録)
- **qwen3-8b は 2k のみ。** 8k 以降は LM Studio がキャッシュ命中リクエストで「prompt processing 98.8%」のまま固まる事象が再現し(再ロード 5 回でも)、16k は Metal の GPU メモリ不足(16GB 機)で失敗した。失敗は `results/long_report.md` に記録。**モデル間の長文比較は未達。**
- 4k / 64k は未実施。32k は全文(L0/JSON)が実行不能(prefill > 15 分、コンテキスト超過)のため圧縮形式のみ。16k は 8 変種に絞った。
- gemma の実効コンテキストは `-c 36000` 指定でも 19456 だった(qwen は 20000 で読み込み)。
- メモリ/KV: LM Studio は API を提供しないため、RSS とシステム使用量の差分のみ。ばらつきが大きく**比較には使えない**。
- 数値・属性の正誤は部分文字列一致。同一文書の問題を全変種が共有するため、変種間の誤りは相関している。
- `則` 演算子は未実装。QA は生成データ(テンプレート由来)で、語彙・文型の多様性は限定的。
- 実験は gemma の凡例なし/ありを含め seed 1 の 1 文書/長さのみ。seed 間のばらつきは未評価。
