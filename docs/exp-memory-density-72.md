# Issue #72: パーソナル AI の長期記憶(会話 → 抽出 → SeCF-L1)と Memory Density

[← README に戻る](../README.md) ・ [#59 Long-term Memory](exp-mem-secf1.md) ・ [#57 同一 budget](exp-33-chat-style.md) ・ [#60 文章長](exp-60-length-breakeven.md) ・ [#69 キャッシュ](exp-cache-69.md)

#69 までの記憶は「人物 × 出来事 × 状態」の人工的な短文で、実際のパーソナル AI が保持する「ユーザー自身の記憶」とは分布が違った。ここでは、人工ユーザーの複数日の会話から長期記憶を**抽出**し(蒸留)、それを SeCF-L1 に書き直し(表現圧縮)、圧縮を 2 段階に分けて測る。仮説は「SeCF-L1 の主な価値は処理速度ではなく、有限の context / cache budget に有用な記憶を高密度に残す Memory Density にある」。`machine_kanbun/jpmemdens.py`(`gen` / `extract` / `convert` / `qa` / `budget` / `cache`)、`machine_kanbun/jpmemdensreport.py`、`scripts/run_dens72.sh`、結果は `results/jp7/`([dens_report.md](../results/jp7/dens_report.md))。

## 設計
- **データ**(実データなし): 人工ユーザー 10 人 × 10 日分の会話。1 人あたり gold 事実 30 件(嗜好・興味・プロジェクト・方針・人物関係・所有物・将来計画・過去の経験・習慣)。**更新・撤回の連鎖**(実装言語の移行、PC の候補追加→決定、旅行先の変更、ダイエットをやめた、動画サービスの解約)と、**未確定**(転職を迷っている)を含む。gold は規則で作り(LLM に作らせない)、会話は gemma-4-12b が gold 事実から日ごとに書いた(各日 16〜24 行、半分以上は事実と無関係な雑談)。全 100 日分で、gold 事実のキーワードが会話に含まれることを確認した(欠落 0)。質問は 1 人 27 問(全体で final 230、history 30、uncertain 10)。
- **記憶の作り方**(gemma): **統合**(10 日分の会話全体から 1 回で抽出。更新は最新の状態に統合)と **日ごと**(その日の会話だけから抽出して日付順に連結。古い状態も残る)。各行を `jpchat.secf1_text` で SeCF-L1 に書き直し(1 行ずつ)、SCF-L1(sudachi-m)を対照にした。
- **評価**: 記憶全文を渡した QA(短い語句で回答、キーワード照合。更新前の古い値だけを答えたら stale)、記憶に残った gold 事実の割合(キーワードの決定的な照合)、同一 token budget(日ごと記憶を、全 NF 記憶の o200k 数の 0.25 / 0.4 / 0.6 倍まで、古い日から切り捨て)、Prefix/KV キャッシュ(各ユーザーの記憶を先頭に置き、20〜32 人分を K=4 スロットで 3 回巡回、表現ごとにモデルを再読み込み)。
- 回答キーワードは、パイロットの回答を見て「未確定」「中止」「していません」などを追加した(保存済みの回答を現在の語彙で再採点している。gold の値は変えていない)。

## 結論
1. **圧縮の大部分は蒸留で、SeCF-L1 の上乗せは小さい(観察)**: 会話 5,457 トークン → NF 記憶 382(統合、0.070)/ 901(日ごと、0.165)。NF 記憶 → SeCF-L1 は 0.898 / 0.916(行ごとの平均 0.909)。会話 → SeCF-L1 の 0.063 / 0.152 は「蒸留 × 表現圧縮」で、SeCF-L1 が会話を 94% / 85% 圧縮したとは読まない。
2. **Memory Density は蒸留で約 6〜12 倍、SeCF-L1 でさらに約 9〜10%(観察)**: 記憶に残った final 事実 1k トークンあたり、生の会話 約 4.2、日ごと抽出 NF 25.3 → SeCF-L1 27.5(+8.6%)、統合 NF 51.9 → SeCF-L1 57.0(+10%)。SCF-L1 は 40.8 で、事実が落ちるため NF より低い。
3. **記憶の質を決めるのは抽出の仕方で、SeCF-L1 化ではない**: 統合抽出は事実を落とす(final の残存 0.852、QA 0.752、生の会話 0.956 に対し −20.4pt [−25.6, −15.6])。日ごと抽出は 0.983 残り、QA 0.930(生の会話に対し −2.6pt [−5.9, +0.7]、検出できなかった)。トークンは生の会話の約 1/5。
4. **全文を渡したとき、SeCF-L1 と NF の正答率の差は検出できなかった**: 統合 −0.7pt [−2.2, +0.7]、日ごと −0.4pt [−2.6, +1.9]。1k トークンあたりの正答は SeCF-L1 のほうが少し高い(統合 2.08 vs 1.96、日ごと 1.18 vs 1.12)のはトークンが少ないため。SCF-L1 は NF より −15.2pt [−19.6, −10.7] で、SeCF-L1 より −14.4pt 低い(#33・#59 と整合)。
5. **同一 token budget では SeCF-L1 が NF より +3.0〜3.7pt 高い(観察、限定)**: 0.25 倍 +3.3pt [+1.5, +5.6]、0.4 倍 +3.0pt [+0.4, +5.6]、0.6 倍 +3.7pt [+0.4, +7.0](p = 0.004 / 0.057 / 0.050)。残る行が NF より約 6〜8% 多い(行の割合 0.27 vs 0.26、0.44 vs 0.40、0.64 vs 0.58)ことと対応し、#57 と同様に「保持量の差」で説明できる(表現の効果は分離していない)。SCF-L1 は行が多く残る(0.28 / 0.44 / 0.64)のに、NF より低い(−1.9 / −5.9 / −11.1pt)。
6. **古い値だけを答える誤りはほぼ起きなかった(観察)**: stale は 0〜1.1%(SCF-L1 の budget 条件のみ)。更新があった事実は、統合では最新だけ残るため古い値を答えず、日ごと記憶では日付つきで残るため最新を選べた。history(更新前の値を答える質問、30 問)は日ごと SeCF-L1 0.900 / NF 0.833、uncertain(10 問)は SeCF-L1 0.700 / NF 0.900 だが、**件数が少なく、差は検出できなかった**。
7. **キャッシュ(U=20〜32)で、ヒット率の差は検出できなかった**: どの U でも、どの表現でも 3 ラウンド巡回の 2・3 回目はすべてヒット(1.00)。NF の総 26.4k トークンでもヒット(#69 の 25〜29k での崩壊は再現しなかった。1 件の長さと K が違う)。ラウンド 0(ミス)の TTFT 中央値は NF 8.0〜8.2 秒、SeCF-L1 7.7 秒(約 4〜6% 短い。トークン削減量 約 5% に対応)。ヒット時の平均 TTFT は SeCF-L1 のほうが約 0.3〜0.4 秒長い(1.8〜1.9 vs 2.2 秒。原因は未確認)。#69 と同様に、キャッシュ上では SeCF-L1 の優位は現れなかった。
8. **仮説の評価**: 「SeCF-L1 の主な価値は Memory Density」は**一部支持にとどまる**。密度は +9〜10%、同一 budget で +3〜4pt の保持差は出たが、**パーソナル記憶の密度を決める主因は抽出(約 6〜12 倍)で、さらに抽出の仕方(統合か日ごとか)で QA が 18pt 変わる**。SeCF-L1 は抽出後の二次的な 1 割弱の上乗せで、全文を渡せるなら正答は変わらず(検出できなかった)、キャッシュでは効かなかった。

## 限界
- **合成データ**: 会話は gold 事実から gemma が作り、事実の語りが実会話より直接的で、雑談の混ざり方も人工的。抽出・書き直し・回答のすべてが gemma-4-12b 1 モデル(自己選好の可能性)。ユーザー 10 人、1 人 30 事実、質問 270、history 30 問、uncertain 10 問。
- **規模**: 記憶は最大でも約 900 トークンで、Issue が想定した 2k〜16k トークンの budget は実施していない(budget は全 NF 記憶に対する倍率)。キャッシュの U は 32 まで(NF 総 26k トークン)で、キャッシュの上限は再現・特定できていない。
- **採点**: キーワード照合で、言い換え(「中止しました」など)は語彙を増やして対応したが、取りこぼしや誤許容がありうる(回答は保存済みで再採点できる)。history / uncertain の gold は更新前の値・未確定の語の有無。
- **抽出**: 統合 vs 日ごとの差は、抽出のプロンプトと「会話全体を一度に読む」ことの両方に依存する。統合の事実落ちの原因(プロンプト、長さ、モデル)は切り分けていない。
- 変換コスト(SeCF-L1 化)は #60 と同じで、ここでは新しく測っていない。

## 停止の記録(§14)
- **分かったこと**: 蒸留が密度の大部分を作り、SeCF-L1 は 9〜10% の追加。同一 budget の差は保持量で説明できる。キャッシュでは検出できなかった。
- **分からないこと**: 2k〜16k の実際の budget での差、実会話での抽出、統合抽出が事実を落とす原因、キャッシュ上限付近での NF と SeCF-L1 の差。
- **いま止める理由**: SeCF-L1 の追加効果が 1 割弱で、全文・キャッシュの両方で決定的な差がなく、これ以上同じ設計の規模拡大では結論が変わりにくい。
- **再開条件**: 実会話に近いデータ(長期の実チャットログなど)が得られる、または、抽出段階の改善(統合の事実落ちの抑制)を研究対象にするとき。
