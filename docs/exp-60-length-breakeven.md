# Issue #60: SeCF-L1 の文章長別の圧縮率・TTFT 短縮・変換コストの損益分岐点

[← README に戻る](../README.md) ・ [#59 Long-term Memory](exp-mem-secf1.md)

SeCF-L1(簡潔な自然言語への書き直し)の圧縮率が文章長でどう変わるか、入力トークンの削減が TTFT をどれだけ縮めるか、変換時間を含めても得になる(損益分岐の)長さがあるかを測る。`machine_kanbun/jplen.py`(`build` / `extras` / `convert` / `ttft` / `sim` / `report`)、`scripts/run_len60.sh`、結果は [results/jp5/len_report.md](../results/jp5/len_report.md)・`convert.jsonl`・`ttft.jsonl`・`sim.jsonl`・`chart_len_ratio.svg`・`chart_len_breakeven.svg`。

**設計**: 日本語のみ。文種 3 種 × NF 長 4 水準(o200k トークンで 25 / 100 / 500 / 2000)× 各 20 サンプル(計 240)。**chat**: #33 の合成履歴の連続した往復(25・100 トークンは 1 発話単位。2000 トークンは履歴 2 本をつなげた)、**news**: FLORES-200 の日本語の連続した文、**bullets**: FLORES の文を箇条書きにしたもの(すでに高密度)。変換は gemma-4-12b による SeCF-L1(#33 再実行と同じ書き直し方針に「複数文・複数行でも落とさず同じ順序で書き直す」を追加)。TTFT は NF 本文と SeCF-L1 本文を同じ指示でプロンプトにし、先頭に一意の識別子を入れてプロンプトキャッシュを避け、順序を交互にして 1 回ずつ測定(gemma の実トークン数)。SCF-L1(sudachi-m)はトークン数の参考のみ。意味保持は QA ではなく、埋め込み(qwen3-embedding-0.6b)の cos(NF, 変換後)と、数・カタカナ語・「〜さん」の保持率の代理指標。4000 トークンは未実施。

## 結論(Issue の問いへの回答)
1. **圧縮率は文章長ではなく文体で決まる(H2・H3 は chat で否定、news で弱く支持)**: chat は 25 トークンから 2000 トークンまで 0.74〜0.76 で平坦(長さによる増加なし)。news は 0.88 → 0.81 と緩やかに下がる(長いほど圧縮)が、bullets は 0.84 / 0.84 / 0.87 / 0.81 でほぼ平坦。**同じ長さ(2000 トークン)での文種の差**(chat 0.74、news・bullets 0.81)は、長さによる差(同じ文種で最大 0.07)と同程度。H1(短文は圧縮率が低い)も、chat では 25 トークンで 0.74 と成立しない(news では 0.88 と低い)。
2. **TTFT の絶対的な短縮は長さに比例して大きくなる(H4 支持)**: 25 トークンで ≈0、100 トークンで 0.10〜0.14 秒(7〜10%)、500 トークンで 0.33〜0.59 秒(9〜16%)、2000 トークンで 1.95〜2.53 秒(16〜20%)。gemma の実トークン数での削減率は o200k より小さい(プロンプトの固定部分があるため。chat 2000 で o200k -26% に対し gemma 実プロンプト -20%)。
3. **同期変換では、25〜2000 トークンのどの長さでも SeCF-L1 のほうが遅い(H5 は否定)**: 総差は +1.7 秒(25)、+3.9〜4.1 秒(100)、+14〜18 秒(500)、+58〜61 秒(2000)。**損益分岐点は範囲内に存在せず、変換が節約の約 22 倍かかるので、外挿しても現れない**。同期変換が成り立つには、変換速度が現状の約 22 倍(約 570 NF トークン/秒)以上必要(別の小さい変換モデルや規則での近似など)。「現実的な文章長では同期変換コストを回収できない」。
4. **事前変換した長期記憶では TTFT の短縮が得られる(H6 は条件つきで支持)**: 変換コストを除くと 500 トークンで 0.3〜0.6 秒、2000 トークンで約 2 秒(16〜20%)短縮する。ただし**1 件の文章が約 24〜56 回再利用されないと変換コストを回収できない**(#59 の「約 40 回」と整合)。**入力トークンの 13〜20% 削減(コンテキスト容量の節約)**が、再利用回数が少ない運用での主な利得になる。
5. **意味の保持(代理指標)**: 埋め込みの cos は SeCF-L1 0.947〜0.986(長さによる低下は見られない。chat 2000 が最小 0.947)、SCF-L1 0.759〜0.862。数の保持率は news・bullets の長い文で 0.81〜0.94(bullets 500 が最小 0.81)、カタカナ語は 0.75〜1.00。**「〜さん」の名前は chat では 0.99〜1.00 だが、news・bullets の 2000 トークンでは 0.40 / 0.25**(出現する件数が少なく参考値だが、名前を落とすことがある)。
6. **ルーティングの示唆**(Issue の想定): 短い発話は NF、古い記憶は非同期で SeCF-L1、検索結果を LLM に渡す文脈は NF か SeCF-L1(#59)。長文だからといって同期で SeCF-L1 化する根拠はない。

## 限界
gemma-4-12b 1 モデル、1 台のマシン(変換速度・prefill 速度はハードウェア依存)、TTFT は 1 サンプル 1 回の測定(順序を交互にしたが反復なし)。日本語のみ。文種は 3 つで、chat は合成履歴(assistant の返事も gemma 生成)、news・bullets は FLORES(翻訳文)。技術文・narrative・4000 トークンは未実施。意味保持は QA ではなく代理指標のみ。変換は 1 つの書き直し指示で、別の指示や小型モデルでは変換速度・圧縮率が変わりうる。TTFT 以外の遅延(生成速度、KV キャッシュの再利用)は測っていない。
