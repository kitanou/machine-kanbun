# Issue #39: 多言語 SCF — 段階 1(tokenizer のみのコンパクトさ比較)

[← README に戻る](../README.md) ・ [用語(NF/SCF/SeCF)](terminology.md)

Issue #39 は 10 言語・5 実験を含む大きな課題なので、CLAUDE.md の方針(安い実験から)に従って段階に分ける。**段階 1(本書)**: LLM を使わず、並列 10 文 × 9 言語の NF について、linguistic / token / semantic の 3 つのコンパクトさが言語間でどれだけ乖離するかを測る。`machine_kanbun/mlpar.py`、結果は [results/par/compactness.md](../results/par/compactness.md)・`compactness.csv`。

既存結果との関係: ja/en/ko/zh の多言語圧縮は #11・#19・#31 で測定済みで、ここでの新規性は **tr / vi / ru / ar / eu の追加**と、**linguistic ≠ token ≠ semantic の分離**(#39 の実験 5 の前半)。グリーンランド語は、信頼できる並列訳を用意できなかったため対象外(誤訳で測ると結果を誤らせる)。母語話者または検証済みの並列コーパスが必要。

**設計**: 同じ意味の 10 文(事実の状態 7 種+雑談 3)を ja/en/zh/ko/tr/vi/ru/ar/eu で用意した。人名(Tanaka 等)は全言語でラテン表記に固定し、人名のトークン化の差を混ぜない。1 文 = 1 事実なので「1 文あたり」が「1 事実あたり」。トークナイザは o200k / cl100k(tiktoken)、Qwen3-8B、Llama-3.1-8B(ローカルの tokenizer.json)。

**所見**
- **3 つのコンパクトさは大きく乖離する**: 文字数で見ると ja 0.50・zh 0.33 と英語の半分以下だが、トークンでは ja 1.14〜1.89、zh 0.80〜1.31 と、日本語は英語より多い(o200k で 1.43)。文字数比とトークン比の食い違い(o200k/chars)は ja 2.85・zh 2.88・ko 2.30 と大きく、**文字数ベースの「言語は圧縮しやすい」は token コストの予測にならない**。「語数」(空白区切り)は ja/zh で定義できない。
- **トークンコストは tokenizer 依存が言語で逆転する**: ar は o200k で 1.07 だが cl100k では 2.23。ru は o200k 1.12、Qwen3 1.42。eu は全 tokenizer で 1.46〜1.69 と一貫して高い(能格・膠着で語が長く、語彙に載っていない)。zh は Qwen3 で最も安い(0.80)。
- **言語間のばらつきは tokenizer が新しいほど小さい**: 変動係数は o200k 0.14、Llama-3.1 0.16、Qwen3 0.21、cl100k 0.21、(文字数 0.31、語数 0.48)。tokenizer の語彙が多言語化されるほど、言語間のトークン差は縮む。
- **トルコ語・バスク語など膠着的な言語**: 語数は英語の 0.66〜0.86 と少ないが、トークンは 1.1〜1.7 倍。**1 語が複数のサブワードに割れ、語数の少なさがトークン節約にならない**(Issue の「linguistic compactness ≠ token compactness」の予測と整合)。

**限界**: 10 文だけで、文は短い単文。翻訳は assistant が作成(母語話者の検証なし。特に eu・ar・tr・vi)。人名をラテン表記に固定したため、(特に ja・ar・ru・ko で)実際の人名表記より差が小さく出る。semantic compactness は「1 文 1 事実」で固定したので、ここでの tokens/fact は意味量を独立に測ったものではない。SCF・SeCF の言語別変換、QA、言語間の構造収束、人間の可読性は**未実施**(段階 2 以降)。

**段階 2 の候補**: 各言語の SCF(機能語・冗長語の決定的削除)を作り、同じ 10 事実の QA(状態 7 種)を gemma で回して、(a) 言語別の削除可能率と、(b) SCF 後の QA 一貫性を見る。LLM 推論を伴うため、段階 1 の結果を見てから判断する。
